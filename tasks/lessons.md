# Уроки

## 2026-07-21 — сначала своё досье, потом интернет

**Что произошло.** Роме понадобилось складывание зеркал по I-Bus. Я пошёл искать протокол
веб-поиском, хотя разведка по оригинальному приложению «i-Bus App» была собрана нами раньше и лежит
в `~/bmw-ibus-recon/`. Роме пришлось поправить: «я просил тебя изучить приложение iBus — там была
эта функция!».

**Почему это ошибка.** В досье лежали снятые с ЕГО машины настройки, где прямо стояло
`Mirror folding = true` и `BMWModel = E53` — то есть доказательство, что функция работала именно на
этом автомобиле, а не «поддерживается на E39 по слухам с форума». Внешний источник такого дать не
может в принципе.

**Как применять.** Перед внешним поиском по железу/протоколам машины — сначала `~/bmw-ibus-recon/`
и память проекта. Внешние источники хороши как ВТОРОЙ, независимый источник для сверки: в итоге
байты из APK и из открытых справочников сошлись до последнего байта, и это дало уверенность,
которой ни один из них по отдельности не давал.

## 2026-07-21 — не чинить симптом, не измерив экран

**Что произошло.** На жалобу «кнопки накладываются» я убрал свои недавние строки и объявил починку.
Симптом остался: экран не помещался и до моих правок.

**Почему.** Реальная рабочая область головы — **853×432 dp** (1280×720 px при 240 dpi, минус
системные панели), а все screenshot-тесты рендерят при `Density.MEDIUM`, то есть 1280×720 **dp** —
в полтора раза выше настоящего. В тестах помещается что угодно.

**Как применять.** Для экранов без прокрутки проверять рендер в настоящей геометрии
(`BordComputerScreenshotTest` — образец). Скриншот с самой головы снимается через
`adb -s 127.0.0.1:5555 exec-out screencap -p` (из Termux напрямую `screencap` отдаёт 0 байт).
