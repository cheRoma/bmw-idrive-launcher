# BMW X5 E53 — кастомный Android-лаунчер · Дизайн/спецификация

**Дата:** 2026-07-01
**Статус:** утверждён (готов к writing-plans)
**Автор решений:** Roma (владелец), при участии Council + brainstorming

---

## 1. Контекст и цель

Заменить заброшенный и тормозящий iDrive Launcher (idrive.ibus-app.de) на собственный
быстрый лаунчер для головного устройства BMW X5 **E53**.

- **Железо:** BMW X5 E53 (2005), VIN WBAFB51060LU55379. Головное устройство **XTRONS IQ7439BL**,
  **Android 12**, **рутовано** (Magisk/su), экран **1280×720**, управление — тачскрин (джойстика iDrive нет).
- **Периферия:** USB→I-Bus адаптер Resler; проприетарный **i-Bus App** читает данные с шины
  (у него НЕТ публичного API/broadcast — мы не можем рендерить его данные).

**Главные требования владельца:**
1. Железобетонный **автозапуск i-Bus App** (сейчас запускает вручную).
2. Быстро и отзывчиво (текущий лаунчер тупит).
3. Кнопка **Перезагрузка**.
4. Свой, поддерживаемый; вид — премиальный BMW iDrive F-series.

**Дизайн-фаза завершена.** Все экраны утверждены и опубликованы на https://k73.online/newBMW/:
главный (3×2 night-calm), Музыка, Приложения, Настройки. Стиль: плоские матовые плитки,
тёмный графит, акцент — фирменный BMW-оранж `#FF7E00` дозированно, мягкий серый текст, ночная тема
по умолчанию.

## 2. Меню (финал)

Сетка **3×2**, 6 плиток:

| Плитка | Тип | Действие |
|---|---|---|
| **Музыка** | внутренний экран | now-playing Яндекс.Музыки (MediaSession) |
| **Навигация** | запуск внешнего | Яндекс.Навигатор (Intent) |
| **Приложения** | внутренний экран | сетка установленных приложений |
| **Борткомпьютер** | запуск внешнего | вывод i-Bus App на передний план |
| **Настройки** | внутренний экран | настройки лаунчера |
| **CarPlay** | запуск внешнего | настраиваемое CarPlay-приложение |

Перезагрузка вынесена из главной сетки → отдельная защищённая плитка внутри «Приложения»
(long-press). Телефон и Камера ранее отброшены.

## 3. Архитектура

**Стек:** Kotlin + Jetpack Compose (одномодульное приложение; фолбэк на классические View,
если Compose ощутимо лагает на SoC XTRONS — архитектура при этом не меняется).

### Компоненты

- **HomeActivity** — HOME-лаунчер (`intent-filter`: `CATEGORY_HOME` + `CATEGORY_DEFAULT`),
  никогда не вызывает `finish()`. Хостит Compose-навигацию, показывает сетку 3×2.
- **Навигация (Compose Navigation)** — переходы между Home / Музыка / Приложения / Настройки.
  Внешние плитки — не навигация, а Intent-запуски.
- **AutostartService + BootReceiver** — по `BOOT_COMPLETED` и на первом resume Home запускает
  i-Bus App в фоне с ретраями (см. §4).
- **AppLauncher** (util) — запуск внешних приложений по имени пакета, вывод на передний план,
  обработка «пакет не установлен».
- **MusicController** — обёртка `MediaSessionManager`/`MediaController`; привязка к активной
  сессии Яндекс.Музыки; отдаёт now-playing + транспорт экрану Музыка. Требует Notification Access.
- **RootShell** (util) — выполнение `su -c <cmd>` (reboot, `am start` для автозапуска).
- **ThemeController** — расчёт день/ночь (Авто = закат/рассвет; ручной День/Ночь), драйвит тему Compose.
- **SettingsStore** — Jetpack DataStore: автозапуск on/off, вывод лаунчера на передний план,
  режим темы, пакеты по умолчанию (музыка/навигатор/carplay).

### Поток данных

```
Boot/Wake → BootReceiver → AutostartService.startIBus() [retry loop]
                                    ↓ (root am start + re-foreground Home)
HomeActivity (это HOME → отображается) ── tap tile ──┬─ внутр. экран (Compose nav)
                                                     └─ внешнее приложение (AppLauncher.launch)
Музыка screen  ← MusicController ← MediaSession (Яндекс.Музыка)
Тема           ← ThemeController (таймер заката/рассвета + настройки)
```

## 4. Автозапуск i-Bus App (ядро проекта)

**Поведение выбрано: «тихо в фоне + ретраи».**

- **Триггеры:** `BOOT_COMPLETED` broadcast **И** первый `onResume` HomeActivity
  (XTRONS-головы чаще просыпаются из сна, чем делают холодный ребут — нужны оба).
- **Действие:** через root `am start` запускаем i-Bus App, затем немедленно возвращаем наш
  HomeActivity на передний план (`moveTaskToFront` / повторный `am start` HOME) → i-Bus остаётся
  запущенным в фоне без мелькания его экрана.
- **Ретраи:** проверяем, поднялся ли процесс i-Bus (`pidof`) и/или присутствует USB-адаптер
  (`lsusb`/UsbManager); если нет — повтор с бэкоффом (напр. 3с→6с→12с) до успеха или общего
  таймаута ~90с, затем стоп. Включается/выключается тумблером в Настройках.
- **Тумблер «Выводить на передний план при запуске»** — ОТДЕЛЬНОЕ поведение: при загрузке/пробуждении
  форсим наш лаунчер (HomeActivity) на передний план, чтобы голова всегда стартовала на нашем Home,
  а не на постороннем приложении. i-Bus при этом остаётся в фоне.

**Риск на проверку на устройстве:** действительно ли root `am start` + возврат Home даёт
полностью флеш-фри фоновый старт. Имя пакета i-Bus App — уточнить на устройстве.

## 5. Плитки — детальное поведение

- **Музыка / Приложения / Настройки** → внутренние Compose-экраны.
- **Навигация** → `AppLauncher.launch(navPackage)` (по умолчанию Яндекс.Навигатор). Опциональный
  1-сек сплэш при запуске (Фаза 3).
- **Борткомпьютер** → вывод i-Bus на передний план (уже в фоне; если процесса нет — стартуем как в §4).
- **CarPlay** → `AppLauncher.launch(carplayPackage)` (настраиваемый пакет). Плитка неактивна/скрыта,
  если пакет не установлен.
- **Приложения** → сетка установленных приложений (реальный список через PackageManager, скролл при >8);
  плитка **Перезагрузка** — в дальнем нижнем углу, обособлена оранжевым кольцом + подсказка «удерживать».

## 6. Музыка (MediaSession)

- **Разрешение:** Notification Listener Access (один раз, ведём пользователя в системный экран).
- **Чтение:** `MusicController` привязывается к активному `MediaController` пакета Яндекс.Музыки;
  метаданные (трек, исполнитель, обложка, длительность, позиция), состояние воспроизведения.
- **Транспорт:** `transportControls` — play/pause, skipToNext, skipToPrevious, seek по прогресс-бару.
- **Лайк:** через кастомное действие Яндекса (`sendCustomAction`), если оно экспонируется; иначе
  кнопка лайка скрыта. **Проверка на устройстве.**
- **Холодный старт (ничего не играет):** экран открывается в пустом состоянии («Нет воспроизведения»),
  ждём play. Нажатие play в пустом → запускаем Яндекс.Музыку и воспроизведение (resume последнего).
- **Плейлисты:** сначала пробуем `MediaBrowserService` браузинг (Фаза 3 — **риск:** Яндекс может пускать
  только Android Auto-клиентов). Не пустит → кнопка «Плейлисты» открывает приложение Яндекс.Музыки.

Гарантировано работают now-playing + транспорт; браузинг — неопределённая часть.

## 7. Тема оформления

- **Режимы:** День / Ночь / **Авто**.
- **Авто = по времени (закат/рассвет):** расчёт из геолокации устройства (если есть разрешение);
  фолбэк — фиксированное расписание (напр. ночь 20:00–07:00). Пересчёт периодически и на `onResume`.
- Обе темы тёмные (BMW night премиум); «День» = повышенная яркость/контраст для читаемости на солнце,
  «Ночь» = приглушённый night-calm (мягкий серый текст, дозированный оранж).

## 8. Системные действия

- **Перезагрузка:** long-press плитки → подтверждение прогресс-дугой на удержании → `su -c reboot`
  (полный ребут Android). Защита от случайного тапа.
- **HOME по умолчанию:** объявляем HOME intent-filter; на первом запуске ведём пользователя назначить
  лаунчер по умолчанию (либо, с root, `cmd package set-home-activity`).
- **Root:** требуется для reboot и надёжного автозапуска (`am start`). Голова рутована (Magisk/su);
  при отсутствии root эти функции деградируют мягко (reboot недоступен, автозапуск — обычный `startActivity`).

## 9. Фазы поставки

Строим ядро сначала; каждую фазу можно ставить на машину и проверять.

- **Фаза 1 — Скелет (основная ценность):** HOME-лаунчер, сетка 3×2, запуск внешних приложений
  (Навигатор/i-Bus/CarPlay), автозапуск i-Bus (фон + ретраи), вывод лаунчера на передний план,
  Перезагрузка (root), тема День/Ночь/Авто, базовые Настройки (тумблеры + тема + пакеты по умолчанию).
- **Фаза 2 — Музыка now-playing (MediaSession):** кастомный плеер, транспорт, лайк, пустое состояние.
- **Фаза 3 — Полировка:** эксперимент с Плейлистами (`MediaBrowserService`), доводка Настроек,
  сплэши при запуске внешних приложений.

## 10. Тестирование

- **Headless на VPS (эмулятора нет — нет KVM):**
  - **Robolectric** — логика: `SettingsStore`, расчёт заката/рассвета, машина состояний ретраев
    автозапуска, сборка Intent'ов в `AppLauncher`.
  - **Paparazzi / Roborazzi** — скриншот-тесты каждого Compose-экрана против утверждённых макетов.
- **На машине (финал):** реальный ребут и автозапуск i-Bus с Resler-адаптером, MediaSession с
  Яндекс.Музыкой, назначение HOME по умолчанию, переключение темы.

**Прежде чем собирать:** на VPS ещё НЕ установлены JDK + Android SDK + Gradle — поднять тулчейн.
