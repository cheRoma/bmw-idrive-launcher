# Дизайн: YouTube + VPN (always-on per-app) — v1

**Дата:** 2026-07-06
**Статус:** утверждён (Вариант 1), реализация начата
**Затрагивает:** плитка YouTube в лаунчере (в приложении) + разовая настройка VPN на устройстве

## Цель
Дать в BMW-лаунчере рабочий YouTube. YouTube в РФ не открывается без VPN с обходом DPI. Нужно, чтобы «просто работало»: пользователь тапает плитку YouTube — видео играет; остальные приложения (Яндекс, навигация) идут напрямую, без VPN.

## Ключевое ограничение (почему НЕ root-путь)
Головное устройство (XTRONS QCM6125, Android 13) **не имеет постоянного on-device root**. Magisk не установлен (нельзя — нет доступного USB для fastboot). Root доступен ТОЛЬКО через живой adb-коннект Claude по reverse-тунелю; когда Claude не в сети, `su` на устройстве отсутствует. Поэтому автономный «root-вотчер» + `sing-box` в tun-режиме (требуют root в рантайме) работать сами по себе, пока владелец за рулём, **не могут**. Установка постоянного root через `dd` boot-раздела — риск кирпича, удалённо не делаем.

**Вывод:** VPN должен работать через штатный Android **VpnService** (как все безрутовые VPN). Root нужен только для РАЗОВОЙ настройки (её делает Claude через adb, когда голова онлайн).

## Архитектура (Вариант 1: always-on per-app VPN)

### Сервер — переиспользуем существующий (работы 0)
На VPS `31.128.34.112` (Латвия, RETN — вне РФ ⇒ YouTube доступен) уже поднят **3x-ui / xray** с инбаундом **VLESS + Reality**:
- порт `4443`, tcp, security=reality, маскировка SNI `www.google.com`, fingerprint `chrome`, spiderX `/`
- клиент **`x5`** уже заведён (UUID + flow `xtls-rprx-vision`)
- publicKey/shortId берём из панели/конфига (сверены: derive из privateKey == publicKey в базе 3x-ui)
Секреты (UUID, publicKey, shortId) НЕ храним в git — только в конфиге на устройстве.

### Клиент на голове — sing-box for Android (SFA)
- Приложение **`io.nekohasekai.sfa`** (официальный sing-box, VpnService, без root в рантайме).
- Профиль: VLESS+Reality-outbound с параметрами клиента `x5`; inbound `tun`; DNS через прокси.
- **Режим:** системный **«Постоянный VPN» (always-on)** + **per-app: маршрутизировать ТОЛЬКО `com.google.android.youtube`** (в sing-box — `route` с `package` = только youtube через proxy-outbound, остальное `direct`; либо Android per-app allowlist на VpnService).
- Итог: YouTube всегда через Латвию; всё прочее напрямую; туннель в простое почти ничего не ест; переживает перезагрузки без Claude.

### Лаунчер (собираем в приложении сейчас)
- Новая **плитка «YouTube»** в карусель (TileId.YOUTUBE).
- Тап → `launcher.launch("com.google.android.youtube")`. Никакой VPN-логики в приложении не нужно — VPN прозрачен на системном уровне.
- Если YouTube не установлен — стандартное поведение AppLauncher (no-op/なし); установку YouTube делаем на устройстве отдельно.

## Что делаем когда (разделение)
**Сейчас, в приложении (Claude, оффлайн от устройства):**
1. `TileId.YOUTUBE` в enum; плитка в `defaultTiles` (иконка Outlined.SmartDisplay, label «YouTube»).
2. Обработчик тапа в HomeActivity: `TileId.YOUTUBE -> launcher.launch("com.google.android.youtube")`.
3. Собрать релиз, поднять versionCode, опубликовать OTA.

**Завтра, на устройстве (Claude через adb/Termux, когда голова онлайн; владелец обновляет приложение через «Проверить обновление»):**
1. Убедиться, что установлен `com.google.android.youtube` (если нет — поставить APK).
2. Скачать+установить **SFA** (`io.nekohasekai.sfa`) через adb.
3. Сгенерировать sing-box-профиль из параметров `x5`, импортировать в SFA (через файл/URI или UI-тапы под adb-root).
4. Дать SFA разрешение VpnService и включить как **always-on VPN** (`settings put global always_on_vpn_app io.nekohasekai.sfa`), настроить per-app = только youtube.
5. Тест: YouTube играет через VPN (проверить внешний IP = латвийский из-под YouTube); Яндекс/навигация — напрямую (внешний IP российский); перезагрузка головы → VPN сам поднимается.

## Тестирование
- Плитка: компилируется, рендерится в карусели, тап открывает YouTube (проверю скриншотом на устройстве).
- VPN: из YouTube WebView/логов — латвийский IP; из браузера/другого апп — прямой. Проверка после reboot.

## Риски / открытые вопросы
- SFA per-app + always-on: если сервер недоступен, YouTube не откроется (ожидаемо; не «lockdown» для остального трафика, чтобы не сломать Яндекс).
- Reality на 4443 (не 443) — чуть заметнее для DPI, но уже работает у владельца; не трогаем.
- Импорт профиля в SFA без UI-тапов: если SFA поддерживает import-by-file/intent — используем; иначе Claude импортирует через adb `input` под root.
- YouTube-аккаунт/логин (Premium у владельца) — вводит владелец сам на устройстве.

## Явно вне scope (YAGNI)
- Тумблер VPN в UI лаунчера, ручной вкл/выкл, экран «Подключаю VPN…» — не нужны при always-on.
- Accessibility-вотчер выхода из YouTube — не нужен при always-on per-app.
- Постоянный root/Magisk — отложено (риск кирпича, нет USB).
